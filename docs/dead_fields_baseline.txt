# Grundlinie fuer scripts/audit_dead_fields.py (MF-831)
#
# Die Zahl unten ist die Anzahl der Feldnamen, die in einem oeffentlichen
# Header deklariert sind und im ganzen Baum an KEINER Stelle geschrieben
# werden. Das Tor schlaegt an, wenn sie STEIGT.
#
# Warum eine Grundlinie und keine Null:
#
#   Gemessen am 2026-09-03: 3995 Felder in `include/`, davon 1231 nirgends
#   geschrieben (9 davon `_`-praefigiert, also konventionell Fuellung oder
#   reserviert; 1222 sind Zusagen ohne Einloesung). Ein Tor bei 0 waere
#   heute unpassierbar und damit nutzlos.
#
#   Die 1231 sind kein Befundstapel. Ein grosser Teil gehoert zu
#   Teilsystemen, die der Baum selbst als unfertig fuehrt — die
#   Phantom-API in MF-366 war genau davon ein Ausschnitt und wurde
#   entfernt. Was die Zahl leistet, ist eine OBERGRENZE fuer Vertrauen:
#   solange sie so hoch steht, ist „das Feld existiert" kein Beleg
#   dafuer, dass es gefuellt wird.
#
# Warum das Tor trotzdem traegt — die Rueckprobe:
#
#   Vor MF-829 hatte `uft_fat_detect_t.fat_mismatch` im ganzen Baum genau
#   zwei Fundstellen: seine Deklaration (`uft_fat12.h:330`) und einen
#   LESENDEN Zugriff (`ASSERT(!r.fat_mismatch)`). Keine Schreibstelle.
#   Dieses Tor haette es gelistet. Gemessen an Commit 14da0842.
#
# Grenze des Verfahrens (steht auch im Skript):
#
#   Ein Feld, das auf einer ANDEREN Struktur mit gleichem Feldnamen
#   geschrieben wird, faellt durch. `uft_sector_t.gap_before` ist genau
#   dieser Fall — tot, aber unsichtbar fuer dieses Tor, weil
#   `uft_atarist_macrodos.c` ein gleichnamiges Feld einer eigenen
#   Struktur setzt. „0 gefunden" ist hier keine Entwarnung.
#
# Senken ist erwuenscht, Heben braucht eine Begruendung im Commit.
#
# MF-865: 1231 -> 1229. Die Zahl stand zwei zu hoch — beim Einbau der
# Faehigkeitstabelle gemessen. Dabei meldete das Tor zunaechst DREI
# neue tote Felder (can_detect, can_decode, grenze), und es hatte in
# seinen eigenen Begriffen recht: die Tabelle initialisierte
# POSITIONELL, also wurde kein Feld je namentlich geschrieben. Behoben
# durch benannte Initialisierer — was ohnehin der bessere Code ist,
# weil ein spaeter eingeschobenes Feld sonst still alle Werte
# verschoebe.

#
# MF-867: 1229 -> 1163. Das Tor kannte die Inkrement-Operatoren nicht
# als Schreibweise — ausgerechnet die haeufigste fuer ZAEHLER.
# Aufgefallen an `pll->clamp_hits` (MF-866, mit `++` hochgezaehlt): das
# Feld galt als tot, obwohl es an der einzigen sinnvollen Stelle
# beschrieben wird. Mit der Ergaenzung in `geschriebene_namen()`
# fielen 66 Fehlalarme weg. Ein Tor, das die haeufigste Schreibweise
# fuer die haeufigste Art toter Kandidaten nicht kennt, meldet genau
# dort Fehlalarm, wo man ihm glauben moechte.

#
# MF-868: 1163 -> 1168. Eine ERHOEHUNG, und sie ist begruendet: die
# Messung ist ehrlicher geworden, nicht der Baum schlechter.
#
# Der A2R-INFO-Leser war eine Kopie des WOZ-INFO-Lesers — gleiche
# Feldnamen, gleiche 60-Byte-Annahme (uft_woz.h:126 sagt woertlich
# "WOZ INFO chunk (60 bytes)"). Er schrieb neun Felder, die die
# A2R-Spezifikation gar nicht kennt, mit Werten, die er hinter dem
# nur 37 Byte langen Chunk auflas.
#
# Dieses Tor vergleicht Feldnamen BAUMWEIT, nicht je Struktur. Die
# Schreibzugriffe des A2R-Lesers hielten damit fuenf Felder in
# uft_woz.h und uft_moof.h von der Liste fern, die dort NIE gefuellt
# werden: cleaned, compatible_hw, disk_sides, required_ram,
# largest_track. Nach dem Entfernen gemessen: null Schreibstellen im
# ganzen Baum.
#
# Die fuenf waren also immer tot. Sichtbar sind sie erst, seit die
# Kopie weg ist. Genau davor warnt der Hinweis weiter oben, dort in
# der anderen Richtung: "0 gefunden" ist keine Entwarnung.

#
# MF-1163: 1168 -> 1161. Das Tor meldete elf Feldnamen, die es im Baum
# nicht gibt — und der Satz in seinem eigenen Kopf lautete, es koenne
# "nicht falsch anschlagen".
#
# Die Regel DEKL liess den Trenner zwischen Typ und Name leer sein. Bei
# `unsigned populated;` verbraucht der optionale Praefix `unsigned `
# bereits, also musste der Typteil in den Namen hineinfressen — und weil
# eine Regel beim Zuruecksetzen den SPAETEREN Quantor zuerst aufgibt,
# fand sie `popula` + `ted` und war fertig, bevor sie den Praefix je in
# Frage stellte. Gemessen: 19 Zeilen dieser Gestalt in `include/`, elf
# davon an der Oberflaeche als erfundener Name — `ted`, `de0`, `de1`,
# `irs`, `nge`, `dht`, `unt`, `ead`, `ers` (uft_scp_integrity.h) sowie
# `ull` und `ins` (uft_zellregel.h:106/107, seit Langem im Baum).
#
# Hinter JEDEM der elf liegt ein Feld, das wirklich geschrieben wird:
# 11 Fehlalarme, 0 verdeckte echte Befunde. Deshalb sinkt die Zahl um
# genau elf und nicht um mehr.
#
# Das ist die Gestalt von MF-867 mit umgekehrtem Vorzeichen: dort kannte
# das Tor eine Schreibweise nicht, hier LAS es einen Namen falsch. Der
# Unterschied ist der Preis — ein unbekanntes `++` meldet ein echtes
# Feld zu viel, ein falsch gelesener Name schickt den Leser zu einem
# Feld, das es nicht gibt. Gekostet hat es eine halbe Sitzung: gesucht
# wurde nach `_magic`, `_pad0`, `_pad1`, `_reserved1`, `_reserved2`,
# weil check() sie als "neu u.a." ausgab — es waren die alphabetisch
# ersten der GANZEN Liste. Die Grundlinie ist eine Zahl; welche Felder
# neu sind, kann dieses Tor nicht sagen, und es sagt das seit MF-1163.
#
# Zwei weitere Grenzen sind dabei gemessen und stehen jetzt im Torkopf:
#
#   - AUS-PARAMETER. Ein Feld, das ueber `&out->feld` gefuellt wird,
#     steht nirgends links von einem `=`. Gemessen sind 79 der 1161
#     irgendwo als `&x->feld` uebergeben. Abgezogen wird nichts — eine
#     Adressuebergabe beweist keinen Schreibvorgang —, aber die Zahl
#     wird getrennt ausgewiesen, nach demselben Grundsatz wie die
#     `_`-praefigierte Fuellung.
#   - `volatile` fehlt im Typ-Praefix. Genau eine Fundstelle im Baum
#     (`volatile bool* cancel;`), von alter und neuer Fassung schlicht
#     uebersehen. Nicht blind mitgeweitet.
#
# Selbsttest 3/3 -> 5/5. Die zwei neuen Faelle sind der Rotbeweis
# (`unsigned gezaehlt_wird;` muss als EIN Name gelesen werden, und das
# Bruchstueck `ird` darf NICHT auftauchen) und sein Gegenbeweis (ein nie
# geschriebenes `unsigned`-Feld muss weiterhin gemeldet werden, sonst
# haette die Korrektur das Tor verengt).
#
# Zur Zahl selbst: 1159 ist an DIESEM Baum gemessen. Zuerst stand hier
# 1161 — das war der Wert eines Arbeitsbaums, der zugleich das
# SCP-Integritaetsmodul aus MF-1162 trug (dessen `checksum_stored` und
# `tdht` sind zwei der 79 Aus-Parameter-Faelle). Eine Grundlinie, die
# ueber ihrer eigenen Messung liegt, ist ein Tor, das weniger sieht als
# sein Gegenstand — Klasse Tor 64. Deshalb steht hier der Wert dieses
# Commits, und MF-1162 hebt ihn mit der eigenen Begruendung auf 1161,
# so wie MF-868 es getan hat.

#
# MF-1162: 1159 -> 1161. Eine ERHOEHUNG um genau zwei, und sie ist
# benannt: `include/uft/formats/uft_scp_integrity.h` bringt
# `checksum_stored` und `tdht` mit. Beide WERDEN gefuellt — aber als
# AUS-PARAMETER:
#
#     out->checksum = uft_scp_integrity_verify_checksum(
#             data, size, &out->checksum_stored, &out->checksum_computed);
#     uft_scp_audit_tdht(data, size, &out->tdht);
#
# `checksum_computed` steht daneben und gilt als geschrieben, weil der
# Name im Baum auch links von einem `=` vorkommt — die beiden anderen
# nicht. Das ist genau die Torgrenze, die MF-1163 gemessen und getrennt
# ausgewiesen hat: 79 der 1161 (vorher 77 der 1159) werden irgendwo als
# `&x->feld` uebergeben.
#
# Warum trotzdem gehoben und nicht umgeschrieben: die Felder sind
# richtig gefuellt, der Aufruf ist die einzige sinnvolle Gestalt, und
# eine Zuweisung nur dem Tor zuliebe einzuziehen waere „die Zahl als
# Motiv" (MF-1077) mit umgekehrtem Vorzeichen. Die zwei stehen damit
# sichtbar in der Klasse, die das Tor nicht sehen kann — dafuer ist die
# getrennte Ausweisung da.
